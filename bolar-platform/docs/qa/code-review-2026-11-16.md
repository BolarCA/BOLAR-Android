## File-by-file notes

### Kernel (`packages/api/src/shared`)
- `route.ts`: `defineRoute` registers every route for OpenAPI generation and the bounded-list startup assertion; `mount`
  validates params/query/body with zod, applies auth level and coarse permission, then idempotency. Clean. Gaps: #6.
  `toDto` strips `passwordHash`, `mfaSecret`, `refreshTokenHash`, `tokenHash` on every serialization (good default).
- `context.ts`: bearer token -> session row -> user row on every request (no cache, so revocation is immediate); roles and
  permissions cached per (user, org, session) with explicit invalidation. Cross-tenant via `X-Tenant-Org` requires a
  platform actor plus a live support session or `platform_admin`. Gap: #21.
- `tokens.ts`: HS256 JWT with issuer/audience, opaque refresh tokens hashed at rest. Fine.
- `totp.ts`: RFC 6238 implementation by hand; correct output. Gaps: #13.
- `access.ts`: scoped RBAC (`rolesCovering`) plus ReBAC edges with time windows; denial on a specific resource is 404 and
  audited. Sensitive gate requires an approved request or a `*_sensitive` permission plus declared purpose. Sound.
- `audit.ts`: awaited append-only write with before/after redaction; request fails if audit fails (deliberate).
- `rate-limit.ts`: sliding-window counter, Redis or memory, fail-open, loopback trusted outside production. Correct and
  well tested. Note: MFA verification is not covered by a dedicated policy (#2).
- `cache.ts`, `db.ts`, `queue.ts`: TTL cache with targeted invalidation; `tenantDb(ctx)` throws without tenant context.
  Queue gap: #4.

### Tenancy (`packages/db/src`)
- `tenant-client.ts`: Prisma extension that filters reads, stamps creates, and turns cross-tenant unique lookups,
  updates and deletes into 404. Models are discovered from the DMMF so new models are covered automatically. Gaps: #10,
  #11, #26. Nested `connect` writes are not checked (document this as a known limit).
- `rls.ts`: policy SQL generated from the schema and pinned by a test; `bolar_app` role, owner bypass. Good.
- Module scan: every handler either uses `tenantDb(ctx)` or adds `tenantOrgId` to the global client's `where`; no
  unscoped read of tenant data was found in iam, privacy, document, retention, maintenance, vendor, legal-hold, finance,
  compliance, template, packet-export or audit routes. Global rules/templates are intentionally org-nullable.

### Auth and IAM
- `auth/service.ts`: scrypt passwords, generic login error, lockout, MFA step-up at login, rotating refresh tokens.
  Gaps: #1, #2, #3, #9, #14, #15.
- `iam/routes.ts`: invitations hashed at rest, scope validation against tenant rows, approver cannot revoke own admin
  role, cache invalidation on every grant/revoke. Gap: #8.
- `platform/routes.ts`: support sessions are time-boxed, reason-required and end-able by the agent or a platform admin.

### Finance
- `ledger/service.ts`: balanced-entry assertion, idempotent posting with P2002 race handling, reversal-once rule, pending
  adjustments need a second approver, trial balance and double-entry proof. Solid.
- `payment/service.ts`: provider adapter boundary, payment events recorded idempotently, refund approver must differ
  from the recorder. Gaps: #7, #16, #20.
- `invoice/*`, `accounts/*`: not re-read in depth; covered by 270 API tests.

### Lease, compliance, screening
- `lease/service.ts`: visibility filter by role scope and relationships, party-only roles, guarded state machine with
  overlap and envelope guards, compliance evaluation on `review`, approval blocked on unresolved block hits. Gap: #12.
- `compliance/engine.ts`: declarative condition tree (`eq/neq/gt/.../matches_any`), no dynamic code evaluation. Good.
- `screening/routes.ts`: consent gates the provider call, raw reports restricted behind the sensitive-access gate,
  decisions human-only. Matches the blueprint.

### Integrations and storage
- `integrations/src/adapter.ts`: `verifyHmacSignature` uses `timingSafeEqual`; mode guard forbids production modes outside
  production. `payments/index.ts`: Stripe signature parsing is correct (`t`/`v1`, `${t}.${body}`).
- `integrations/webhooks/index.ts` and `api/.../integrations/webhooks.ts`: persist-once by (provider, externalId), raw
  body preserved for signatures. Gap: #5.
- `storage/*`: keys forced under `org/<tenantOrgId>/`, path traversal rejected, HMAC-signed local URLs with expiry, 404 on
  bad signatures. Gap: #17; `verify` compares with `===` (minor).
- `signature/routes.ts`: DocuSign webhook resolves the envelope by provider id, terminal states never regress, lease
  transition runs as a system actor. Good.

### AI assistant (`modules/ai`)
- `service.ts`: command redacted before storage, plan from provider limited to 3 tool calls, each tool re-runs the route's
  own access checks, outputs redacted, citations enforced, budget pre-checked and charged, full audit row per command.
- `tools.ts`: read-only tools plus two draft tools that go through the human approval queues; document text is passed
  as untrusted data. This is the strongest part of the codebase from a safety standpoint.

### Reporting
- `reporting/service.ts` and `access.ts`: raw SQL over materialized views uses `Prisma.sql` parameters; identifiers are
  compile-time constants; property scope uses `Prisma.join`. No injection path found.

### Web app (`apps/web`)
- `lib/api-client.ts`: access token in memory, single-flight refresh, act-as-org header. Gaps: #18, #24.
- `next.config.ts`: standalone output, dev overlay disabled for e2e. Gap: #23.
- No `dangerouslySetInnerHTML` anywhere; templates escape every variable except on the SMS channel.

### Tests and harness
- 44 unit/API test files, 13 Playwright specs, axe on every portal; e2e now runs against a production build with no
  retries locally. The two e2e flakes found earlier are closed (see `smoke-results.md` items 6 and 7).

### Pass 2A: API domain modules: property, tenant-profile, document, media, notification, notice, template, vendor, maintenance

Scope: every file under `packages/api/src/modules/{property,tenant-profile,document,media,notification,notice,template,vendor,maintenance}` (none of these directories contains a `__tests__` folder; the module tests live in `packages/api/src/__tests__/*.test.ts` and were only skimmed for coverage of the findings below). Items in the "already known" list are omitted.

Kernel fact that drives several findings: `hasScopedPermission` treats any `org`/`platform`-scoped role as covering every resource. `tenant`, `occupant`, `vendor`, `corp_admin`, `landlord` are org-scoped roles (`ROLE_SCOPES`), so wherever a module relies on `requireAccess` alone, those roles get org-wide access to whatever their permission set contains. The property module compensates for `landlord`, maintenance/document/media compensate for tenant/vendor; the gaps are where a module forgot (tenant-profile, notice, maintenance for landlord).

### 2. Per-area notes

**apps/web/app** — Pages are thin wrappers; the real logic lives in components. Login's `?next=` check is the only redirect handling and is bypassable with `//host` (#4). `accept-invite` is safe (token posted, slug-only redirect). The portals layout relies on `AppShell` for role gating, which mirrors `me.portals`; every page also calls `useCan`, and spot-checks against the API (documents delete, notice/lease/export/privacy/legal-hold approve, template approve, compliance activate, support sessions) confirm the API enforces the same rules, so gating is cosmetic in the good sense. The corporate portal's description of its scoping does not match the API (#3). Vendor schedule's comma-separated `status` filter is accepted by `workOrderQuery`'s preprocess, so that `as never` cast is fine.

**apps/web/components** — No `dangerouslySetInnerHTML`; all API text goes through JSX. The remaining XSS sink is `href={sourceUrl}` on compliance screens (#5). Forms collect PII only where the API stores it (tenant profile DOB/SSN last 4, emergency contacts), except Tenant Pay which collects full card/bank numbers and discards them (#11). Approval UIs hide buttons for the author, and the API repeats each check. Accessibility is generally strong (labels, roles, focus trap, skip link); regressions are duplicate ids from label-derived ids in row forms (#21) and the nested-dialog Escape behaviour (#22). `Table` rows with `onRowClick` always carry a keyboard-reachable link/button, so no keyboard trap. `auditManifestUrl` link can never authenticate (#17).

**apps/web/lib** — `api-client` keeps the access token in memory, shares one in-flight refresh promise (no refresh race found), and clears everything on a failed refresh. Act-as org is a localStorage flag attached to every request; starting/stopping act-as clears the query cache and hard-reloads, so cache keys not carrying the org are acceptable, but a stale flag survives into another user's login and locks them out (#6). Query keys never include the user id; `logout()` clears the cache, so stale cross-user data only appears if two users share a tab without logging out. Hooks occasionally skip URL encoding (#23). `portal-home` mirrors the API's finance staff list, which is correct today but will drift.

**packages/contracts** — Schemas are consistent with the Prisma-backed enums used by the web (`LEASE_STATES`, `WORK_ORDER_STATUSES`, etc.); no enum mismatch found between UI option lists and contracts. Gaps: `createInvitation.role` is the full role list (#2), `sourceUrl` accepts any scheme (#5), `recordConsent.consentDocumentId` is free text (#10), and a handful of unbounded strings (#29). `transitionLease.note` is optional in the schema but required by the state machine for reject/terminate, which the UI handles by forcing a note.

**packages/integrations** — Adapters never log secrets and mode resolution refuses `production` outside `NODE_ENV=production`. Weaknesses are operational: mock webhook secrets are public constants (#9), DocuSign swallows provider errors and uses a static token (#12), no fetch has a timeout and `withRetry` retries unknown errors (#13), Stripe webhook has no timestamp tolerance (#19), local storage signing compares with `===` and reuses the JWT secret (#18), the Anthropic answer turn can mismatch tool_use/tool_result (#20). The Plaid adapter discards the access token after exchange (`accessTokenRef` is the item id), so bank linking is a stub rather than a bug.

**packages/shared** — `rbac.ts` is internally consistent with `ROLE_SCOPES`, but the matrix gives several roles both sides of two-person gates and lets `government` request arbitrary exports (#7, #15); `org_admin` holds `support_session:start` which the API neutralises with an `isPlatform` check. `pagination.decodeCursor` is unvalidated but every caller only reads `.id` for a Prisma cursor on a tenant-scoped query, so tampering only changes the page start. `money.ts` is integer-cents only. `redaction.ts` is both too broad and too narrow (#26). `state-machine.ts` and `classification.ts` are fine.

**packages/db/seed, password.ts** — scrypt with per-hash parameters and `timingSafeEqual`; fine. Seeds are tenant-consistent (every edge and row carries the demo org id; no cross-tenant edges). Notable: rules seeded active without second-person approval and inconsistent classification of SSN-bearing profiles (#27); the platform admin, the `gov` and `corp` personas are created in the same org scope, which is what makes #3 visible in the demo.

**.github / infra / scripts** — The staging deploy gate inspects the wrong commit (#1); otherwise there is no untrusted `${{ github.event.* }}` interpolation in `run:` blocks, SSH scripts use only `github.sha`/`repository_owner`, and secrets are not echoed. Dockerfiles run as `node`, API image has a HEALTHCHECK, web/workers do not. Staging compose exposes API and web directly and lacks healthchecks (#14). Workflows lack `permissions:` and SHA pinning (#28). Scripts pass DB passwords on the command line (#30); `uat-smoke.sh` seeds whatever `DATABASE_URL` points at (covered by the already-reported seed guard finding).
